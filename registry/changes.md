## Decided (Carlos, 2026-09-30)

- The line stores its code, so anyone scanning lines can refund and every code can be read from the
  accounts alone.
- The proof is the consent: the profile key signs nothing, anyone may send any instruction.
- One proof per transaction: `register` takes one; each extra root is its own `add_proof`.
- No root twice in a line (forced by the above: otherwise a stranger could fill a line by replaying
  one public proof).
- The scope namespace is `forest.foundation/label/v1/`.
- Readers decide: "badged" means backed by a root the reader trusts; issuers publish signed roots on
  a schedule; apps prove against the newest.

## Chosen, not decided (the brief was silent; the option that adds the least)

1. An empty label is allowed (0 to 128 bytes): the program does not care what the text says.
2. A line grows 32 bytes per root instead of being allocated for sixteen, so a typical line's
   deposit is about half.
3. No events: a line is an account, and readers read accounts.
4. `refund` with nothing above the minimum fails rather than doing nothing, so nobody pays a fee for
   a no-op.
5. A new placeholder program id in the source, `FoRBadgeLineFreeNoFeeNoAdmin1111111111111111`.
6. The message namespace stays `forest.foundation/profile/v1/`; it now hashes the key alone.
7. On devnet the two issuers' lists are stand-ins the script makes, recorded as such: no issuer
   publishes a list yet.

## Learned

- One proof costs about 120,000 compute units (124,218 for a register under LiteSVM, 120,920 on
  devnet), so two in one transaction would exceed the default 200,000 for one instruction.
- A line with a 15-byte label and one root is 168 bytes: 0.0015 SOL of deposit at today's rate,
  0.0002 after the rent cuts, 0.00016 more per root today.
- The runtime refuses a small refund to a payer holding no SOL (it would leave the payer below its
  own minimum); it lands once the payer holds some.
- The public devnet RPC answers `getProgramAccounts` for this program with a profile filter.
- The deploy key held 4.317 SOL before this deploy; 3.356 after.
